# GAME-DESIGN.md — the rulebook for every NEW game (owner, Oct 21 2026, from the advisor)

Applies to every NEW game, starting after the 6 current games are done (LATER.md). The 6 games keep their short lists
(rules/short/). Every new-game plan (plans/<game>.md) answers these six in order, one line each, before any building.

1. **Grey-box fun in 30 seconds.** Build the game first with plain grey shapes and NO art, models, sound or menus. A
   person must have fun within 30 seconds of the first touch. If the grey box isn't fun, art won't save it - stop.
2. **Small scope.** One core action, one mode, one place to start. Write what is NOT in the first version. More
   modes, levels and unlocks come only after the core is proven fun and finished.
3. **Teach by playing.** No text walls, no tutorial screens. The first 30 seconds are built so the player learns by
   doing it (one control at a time, safe to fail). If something needs explaining, the level teaches it.
4. **Steal the shape, invent one thing.** Take the proven shape of a game people already love (its loop, pacing,
   controls) - then add ONE new idea of our own that makes it ours. Never copy art, names or characters (FAMILY-RULES,
   ASSET-LAW).
5. **Content as data.** Levels, tracks, teams, events, prices and difficulty live in plain data files (JSON/lists),
   not inside the game code - so new content is a data edit, a tester can change one number, and the robot can check
   each entry.
6. **Kill early.** Every new game has a go/no-go after the grey box and after the first playable: if it is not fun or
   not reaching its plan, it is shelved - no rescue jobs. A shelved game costs days, a rescued bad game costs weeks.
