# STORE READINESS — can Apex Arcade (one app, home for all games) go on the App Store and Google Play? (Window 11 - Senior Advisor, Oct 22 2026)

Checked against the stores' published rules on Oct 22 2026 (links below). **Short answer: yes — both stores have a written path for exactly this shape of app.** The conditions below are the price. Anything not confirmed in the published text is marked UNVERIFIED.

## Bundled vs downloaded game code — the heart of it
- **Apple allows it, by name.** Guideline 4.7 covers software "not integrated into the binary, especially HTML5 and JavaScript mini apps and mini games." The host app is responsible for every title complying with all guidelines. Conditions: each title follows the privacy rules (5.1); the app must offer content filtering, a reporting mechanism with timely response, and blocking of abusive users (4.7.1); digital goods follow Guideline 3.1 payments (4.7.1); the app must not expose native platform APIs to the downloaded software without Apple's prior permission (4.7.2); data/privacy permissions are never shared with an individual title without the user's explicit consent each time (4.7.3); on request the developer must provide an **index of all software and metadata in the app, with universal links to every title** (4.7.4); users must be able to identify titles that exceed the app's age rating, with age-gating for minors (4.7.5). The general rule 2.5.2 (apps are self-contained; no downloading code that changes functionality) is exactly why the games must live inside 4.7's terms and use WebKit/JavaScript only. Apple tightened 4.7 in Nov 2025 and again Oct 2026 — re-read it at submission.
  - https://developer.apple.com/app-store/review/guidelines/ (§2.5.2, §4.7) · changes: https://developer.apple.com/news/?id=ey6d8onl · https://developer.apple.com/news/?id=92th7e5i
- **Google allows the interpreted half, bans the executable half.** Play's Device and Network Abuse policy: an app may not update itself except through Play, and may not download executable code (dex, JAR, .so) from outside Play — **but this restriction does not apply to code running in a VM/interpreter with indirect API access, "such as JavaScript in a WebView."** Runtime-loaded interpreted code must not enable policy violations. So: HTML/JS games loaded into a WebView are within the published rule; downloading native game code is not.
  - Developer Program Policy (Device and Network Abuse): https://storage.googleapis.com/support-kms-prod/zo7U9w2VUzeeH5zq00HdOMqveFtMBWkkNonZ

## Minimum functionality, templates, spam
- **Apple 4.2**: an app must go "beyond a repackaged website"; not useful/unique/app-like = rejected. **4.2.2**: not primarily marketing, web clippings, a content aggregator or a collection of links (catalogues excepted). **4.2.6**: template/generation-service apps are rejected unless submitted by the content's own provider — the Arcade must be submitted under the owner's own developer account. **4.3**: no multiple bundle IDs for the same app — Apple literally tells developers to ship one app with variations inside it, which is the Arcade's shape.
- **Google, Spam and Minimum Functionality**: apps must offer a basic degree of functionality and a respectful experience; broken functionality (crashes, freezes, won't load) is banned; WebView/affiliate spam is banned (a WebView of your own content, with real app function, is a different case); **Repetitive Content**: developers making multiple similar small apps "should consider creating a single app that aggregates all the content" — again, the hub shape is what the rule pushes toward.
  - Same policy document as above (Spam and Minimum Functionality sections).

## Casino-style titles, tournaments, age ratings
- The public Arcade carries **no casino content** (owner's standing rule) — this page records what the stores would say if that ever changed.
- **Real-money gambling**: Apple 5.3.4 — licensed only, geo-restricted, free download. Google — licensed operators only, per-country approval, AO (Adult Only) rating, no Play billing for it. Neither store is a casual path.
  - https://developer.apple.com/app-store/review/guidelines/ (§5.3) · https://support.google.com/googleplay/android-developer/answer/9877032?hl=en
- **Simulated gambling** (casino-style, no real money): allowed by both, but it is an age-rating driver. Apple rates via App Store Connect questionnaire (gambling descriptors raise the rating); Google via the IARC questionnaire, where "simulated gambling" is a named descriptor and ratings vary by territory (the generic IARC scale permits it from 12+). Exact floor for a given territory: **UNVERIFIED** — read it off the completed questionnaire at submission. Apple 5.3.1–5.3.2: contests/sweepstakes must be developer-sponsored with official rules in-app stating Apple is not a sponsor. Both stores: paid random-item mechanics ("loot boxes") must disclose odds before purchase (Apple 3.1.1; Google Payments policy).
  - Content ratings (Play Help): https://www.dejavu.org/cgi-bin/get.cgi?ver=95&url=https%3A%2F%2Fsupport.google.com%2Fgoogleplay%3Fp%3Dappgame_ratings

## Privacy and data
- **Apple 5.1.1(i)**: privacy policy linked in the store metadata and inside the app, stating what is collected, retention/deletion, and how consent is revoked. **5.1.1(v)**: if the app offers account creation, it must offer **account deletion inside the app**. App Privacy details ("nutrition labels") in App Store Connect must match reality. **5.1.2(i)** (Nov 2025): sharing personal data with third parties — **including third-party AI** — must be clearly disclosed, with explicit permission first.
- **Google**: a completed **Data safety** section (what is collected/shared, encryption, deletion) and, if the app allows account creation, an **in-app deletion path plus a public web link** for deletion requests.
  - https://support.google.com/googleplay/android-developer/answer/13327111?hl=en-IN
- **Payments (read this twice)**: digital goods and subscriptions sold **inside** the apps must use the store's billing — Apple In-App Purchase (Guideline 3.1.1; §4.7.1 applies Guideline 3.1 to mini-game software too) and Google Play Billing (Payments policy: subscriptions are a named example). The website checkout that bills today's subscriber does not satisfy either store inside the app. External-purchase-link programs exist in some regions; whether they fit this app exactly is **UNVERIFIED** — settle at submission, not by assumption.
  - https://support.google.com/googleplay/android-developer/answer/10281818?hl=en&ref_topic=12798386

## AI-generated content
- Neither store's published rules regulate **how the app was built** — no rule found requiring disclosure that AI wrote the code. (Searched Oct 22 2026; absence noted, not proof for all future versions.)
- The rules bite when the app **generates content for users at runtime**. Google's AI-Generated Content policy defines it as content created by generative AI **from user prompts** (chatbots, prompt-to-image): such apps must prevent restricted content and provide **in-app reporting/flagging** of offensive content. Apple's 1.2 (user-generated content) requires filtering, reporting with timely response, and blocking — extended Oct 2026 to apps that let users create/generate content — and 4.7.1 repeats the same trio for mini-game hosts. Our friends/chat features already sit under 1.2-style duties on both stores.
  - https://support.google.com/googleplay/android-developer/answer/13985936?hl=en-GB · https://developer.apple.com/app-store/review/guidelines/ (§1.2, §4.7.1)

## Five yes/no checks — add to the launch gate (Gate 4, LIVE)
1. Is every game the app offers listed in an index (title + link) that App Review can open, with nothing hidden, dormant or undocumented? YES / NO
2. Does every game run only as interpreted code (WebKit/JavaScript on Apple, WebView JavaScript on Google), with no native APIs exposed to downloaded games and no executable code ever downloaded? YES / NO
3. Is the subscription sold inside each app only through that store's billing (Apple IAP / Google Play Billing)? YES / NO
4. Do the privacy declarations match reality on both stores, with in-app account deletion working and any data shared with third-party AI disclosed and consented? YES / NO
5. Is the catalogue free of casino-style and real-money content, and does the app's age rating cover its highest-rated game, with age-gating where a title exceeds it? YES / NO
