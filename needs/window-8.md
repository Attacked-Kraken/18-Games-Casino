# Window 8 - what would get a sent-back game right the FIRST time

1. Complaints become measurements before any code: each send-back line is rewritten as a DONE.md / REALITY.md check with numbers - players are the rigged base-human-v2 bodies at 1.75-1.95 m, sharp means the robot's blur check passes at full resolution, a close camera means the player fills a set share of the frame from frame 1. A redo starts from that pass/fail list, not from the complaint words.
2. A tester plays the CURRENT build first and files a failing tester- play test for every complaint line. The redo is done when those exact tests pass on the new build - never when the code changes land.
3. Assets before code: the models and textures are chosen and owner-approved up front (SEARCH lines, owner picks when there is a choice) and measured from the files themselves. "Not real 3D" and "blurry" are asset decisions, and they are cheapest before a single line is built.
4. Build in slices and look at the robot's pictures after each one - menu, gameplay, and the close-up of the main player. A wrong look then costs one slice instead of a whole game, and nothing is called done on a merge alone: merged, NOT yet seen, until the pictures pass.
5. Independent tester sign-off with numbers before it reaches the owner: sizes, ground contact and camera framing measured in the running game, and the report names what was NOT tested instead of claiming done.
